# 시설 보수 접수 (해썹생산시설 · 영도 · 온천 · 마린 · 도모헌)

현장 직원은 로그인 없이 접수하고, 관리팀과 해썹 확정 담당자는 구글 계정으로 로그인해 처리합니다.
모든 접수 건은 **구글 시트 한 줄**로 쌓이고, 사진과 완성된 Word 접수서는 **구글 드라이브 폴더**에 저장됩니다.

```
현장 접수 ──▶ (해썹만) 확정 담당자 확정 ──▶ 관리팀 처리방안 ──▶ 관리팀 처리결과 ──▶ 수선 완료 체크
                                                                       해썹: 확정 담당자 / 매장: 관리팀
                                                                       → 완성된 접수서가 드라이브에 자동 저장
```

## 구성

| 파일 | 하는 일 |
|---|---|
| `index.html` | 앱 화면 (GitHub Pages로 공개) |
| `config.js` | 연결 설정 두 줄 (아래 6단계에서 입력) |
| `template.js` | 원본 접수서 Word 양식 (바꾸지 마세요) |
| `apps-script/Code.gs` | 구글 시트에 붙이는 연결 프로그램 |

## 설치 (처음 한 번, 약 20분)

회사에서 쓰는 구글 계정 하나로 1~5단계를 진행하세요. 이 계정이 시트·드라이브의 주인이 됩니다.

### 1. 구글 시트 만들기
1. [sheets.new](https://sheets.new)에서 새 시트를 만들고 이름을 `시설보수 접수`로 바꿉니다.

### 2. 연결 프로그램 붙여 넣기
1. 시트 메뉴 **확장 프로그램 → Apps Script**를 엽니다.
2. 왼쪽 `Code.gs`의 내용을 모두 지우고, 이 저장소의 `apps-script/Code.gs` 내용을 통째로 붙여 넣은 뒤 저장(💾)합니다.

### 3. 로그인용 키(OAuth 클라이언트 ID) 만들기
1. [console.cloud.google.com](https://console.cloud.google.com)에 같은 계정으로 들어가 새 프로젝트를 만듭니다 (이름 예: `facility-repair`).
2. **Google 인증 플랫폼(또는 API 및 서비스 → OAuth 동의 화면)** 에서 앱 정보를 입력합니다.
   - 회사 구글 워크스페이스 계정이면 사용자 유형 **내부**를 고르세요. 회사 계정만 로그인할 수 있습니다.
   - 일반 Gmail이면 **외부**를 고른 뒤, 마지막에 **앱 게시(프로덕션으로 전환)** 를 꼭 눌러 주세요. 안 누르면 등록한 테스트 사용자만 로그인할 수 있습니다.
3. **클라이언트(또는 사용자 인증 정보) → 클라이언트 만들기 → OAuth 클라이언트 ID**
   - 애플리케이션 유형: **웹 애플리케이션**
   - 승인된 JavaScript 원본: `https://<GitHub 아이디>.github.io` (뒤에 `/`나 저장소 이름은 붙이지 않습니다)
4. 만들어진 **클라이언트 ID** (`…apps.googleusercontent.com`)를 복사해 둡니다.

### 4. 연결 프로그램 준비
1. Apps Script의 `Code.gs` 맨 위 `CLIENT_ID: '…'` 따옴표 안에 3단계의 클라이언트 ID를 붙여 넣고 저장합니다.
2. 위쪽 함수 목록에서 **setup**을 고르고 **실행**합니다.
3. 권한 요청 창이 뜨면 계정을 고르고 허용합니다. "확인되지 않은 앱" 경고가 나오면 **고급 → (프로젝트 이름)(으)로 이동**을 누르면 됩니다. 직접 만든 프로그램이라 나오는 경고입니다.
4. 시트에 `접수` · `사용자` · `기록` 탭이 생기고, 드라이브에 `시설보수_자료` 폴더(`사진`, `접수서`)가 생깁니다.

### 5. 웹 앱으로 배포
1. Apps Script 오른쪽 위 **배포 → 새 배포 → 유형 선택(⚙) → 웹 앱**
   - 실행 계정: **나**
   - 액세스 권한: **모든 사용자**
2. **배포**를 누르고 나온 **웹 앱 URL** (`https://script.google.com/macros/s/…/exec`)을 복사합니다.
3. 그 주소를 브라우저에서 열어 `{"ok":true,…}`가 보이면 성공입니다.

### 6. GitHub Pages로 화면 올리기
1. 이 저장소의 `config.js`를 열어(연필 아이콘) 두 값을 채우고 저장(Commit)합니다.
   ```js
   SCRIPT_URL: "5단계의 웹 앱 URL",
   CLIENT_ID: "3단계의 클라이언트 ID",
   ```
2. 저장소 **Settings → Pages → Build and deployment**에서 Source를 **Deploy from a branch**, Branch를 **main / (root)** 로 정하고 Save.
3. 1~2분 뒤 `https://<GitHub 아이디>.github.io/<저장소 이름>/` 이 앱 주소가 됩니다. 이 주소를 직원들에게 공유하세요.

### 7. 관리팀·확정 담당자 등록
처음에는 setup을 실행한 계정만 관리팀으로 등록되어 있습니다. 그 계정으로 앱에 로그인해 오른쪽 위 **사용자 관리**에서 인원을 추가하세요. 시트의 **사용자** 탭에 직접 적어도 됩니다. 어느 쪽이든 바로 적용됩니다.

| 이메일 | 이름 | 역할 |
|---|---|---|
| kim@회사.com | 김관리 | 관리팀 |
| lee@회사.com | 이확정 | 확정담당자 |
| park@회사.com | 박팀장 | 열람 |

- **관리팀**: 접수 내용 수정, 처리방안·처리결과 입력, 매장 건 수선 완료 체크, 삭제, 사용자 관리
- **확정담당자**: 해썹 건 확정·반려, 해썹 건 수선 완료 체크
- **열람**: 전체 목록과 처리 내용 보기만
- 두 역할을 함께 줄 때는 `관리팀,확정담당자`처럼 쉼표로 적습니다.
- 명단에 없는 사람도 로그인 없이 접수는 할 수 있고, 자기가 접수한 건의 진행 상태는 그 기기에서 볼 수 있습니다.

## 데이터가 쌓이는 곳

- **시트 `접수` 탭**: 한 줄이 한 건입니다. 상태, 사업장, 소속팀, 확정자, 처리 업체, 완료일, 체크자, 사진 링크, Word 접수서 링크가 모두 칸으로 나뉘어 있어 필터·피벗·차트로 바로 집계할 수 있습니다. 회색 머리글(`_id` 등) 칸은 프로그램용이니 고치지 마세요.
- **시트 `기록` 탭**: 누가 언제 접수·확정·처리·체크했는지 한 줄씩 남습니다.
- **드라이브 `시설보수_자료/사진/년-월`**: 현장·완료 사진
- **드라이브 `시설보수_자료/접수서/사업장/년-월`**: 수선 완료 체크 때 자동 저장되는 Word 접수서. 같은 건을 다시 저장하면 새 파일로 바뀝니다.

## 고칠 때

- `Code.gs`를 바꾼 뒤에는 **배포 → 배포 관리 → ✏️ 편집 → 버전: 새 버전 → 배포**를 해야 반영됩니다. 웹 앱 URL은 그대로 유지됩니다.
- 사업장·소속팀·해썹 구역(실) 목록은 `index.html`과 `apps-script/Code.gs` 두 곳의 `SITES`, `TEAMS`, `ROOMS`를 같이 바꿉니다.
- 이미 시트를 만든 뒤 새 버전의 `Code.gs`로 바꿨다면 `setup`을 한 번 더 실행해 새 칸의 머리글을 채워 주세요. 기존 데이터는 그대로 남습니다.
- 접수 건을 앱에서 삭제하면 시트에는 상태 `삭제`로 남습니다. 데이터는 지워지지 않습니다.

## 알아 둘 점

- 앱 주소를 아는 사람은 누구나 접수할 수 있습니다. 주소는 사내에만 공유하세요.
- 사진은 "링크가 있는 사람 보기"로 공유되어야 시트 미리보기와 앱 썸네일에 보입니다. 회사 정책으로 막혀 있으면 앱은 연결 프로그램을 거쳐 사진을 보여 주고, 시트 미리보기 칸만 비게 됩니다.
- 구글 무료 사용량 안에서 동작합니다. 매장 5곳 규모의 접수량이면 충분합니다.
